# Как устроен FarchiOs

## Идея

FarchiOs — не «ещё один форк пакетов», а **слой готовности поверх Arch**.
Всё, что можно не форкать, не форкается: пакеты берутся из официальных
репозиториев Arch, а FarchiOs добавляет:

1. **Правильный набор пакетов** — чтобы после установки не надо было гуглить
   «как поставить Steam на Arch».
2. **Тюнинг, который не ломает систему** — консервативные значения sysctl,
   zram вместо swap-раздела, udev-правила для NVMe.
3. **Утилиту `farchios`** — вместо README на 300 строк.
4. **Брендинг** — чтобы `neofetch`/`fastfetch` показывал FarchiOs, а не Arch.

Это осознанный компромисс: меньше риска сломаться при обновлениях, но и
меньше «уникальности» по сравнению с Manjaro или CachyOS.

## Что происходит при сборке

1. `mkarchiso` читает `profiledef.sh` → имя, версия, режимы загрузки.
2. `pacstrap` ставит пакеты из `packages.x86_64` в `work/x86_64/airootfs`.
3. В chroot копируется `airootfs/` поверх установленной системы.
4. Выполняется `root/customize_airootfs.sh`: локаль, live-пользователь,
   сервисы, автологин.
5. `mkinitcpio` собирает initramfs (`archiso`-хук).
6. Корень пакуется в squashfs (xz + bcj x86), кладётся на ISO.
7. `systemd-boot` / `syslinux` + `grub` делают образ загрузочным.

## Разделение «live» и «установленная система»

Это важная деталь, на ней легко ошибиться.

| Файл | Где работает |
|---|---|
| `airootfs/root/customize_airootfs.sh` | только при **сборке** ISO, в chroot |
| `airootfs/usr/local/bin/*` | в live **и** в установленной системе |
| `farchios-firstboot.service` | только в установленной (в live отключён) |
| `farchios-postinstall` | только в установленной, вручную |

Установленная система — это `archinstall` + пакеты из
`/etc/farchios/postinstall-packages.txt`. Она не наследует файлы из
`airootfs` автоматически, поэтому `farchios-postinstall` доустанавливает
брендинг, драйверы и тюнинг.

## Почему archinstall, а не Calamares

Calamares для Arch собирается из AUR и требует своих модулей
(`unpackfs` с squashfs, `bootloader`, `displaymanager`), которые ломаются
при каждом крупном обновлении. `archinstall` — официальный пакет Arch,
обновляется вместе с системой и умеет ровно то же, что нужно.

Calamares остаётся в roadmap как «красивый» вариант для релизных сборок.

## Почему systemd-boot, а не GRUB (для UEFI)

- Быстрее и проще.
- Не требует `grub-mkconfig` и `os-prober`.
- Меньше кода = меньше поверхности для поломки.

GRUB оставлен в ISO для BIOS-загрузки (`bios.syslinux` — syslinux, а
`grub/grub.cfg` используется как резерв).

## Тюнинг: что и зачем

| Настройка | Значение | Почему |
|---|---|---|
| `vm.swappiness=10` | 10 вместо 60 | игра не должна уходить в swap при живой RAM |
| `vm.max_map_count=2147483642` | максимум | некоторые игры на Proton падают с дефолтным |
| `vm.dirty_ratio=15` | выше | меньше микро-фризов при записи шейдер-кэша |
| zram `min(ram/2, 16384)` | zstd | быстрее диска, не изнашивает SSD |
| NVMe `scheduler=none` | — | у NVMe нет пользы от bfq, лишний оверхед |
| `RADV_PERFTEST=gpl` | — | gamescope/Vulkan поверх Wine быстрее на RADV |
| `MESA_SHADER_CACHE_MAX_SIZE=12G` | — | кэш шейдеров Steam не чистится каждую сессию |
| `DXVK_HUD=fps` | — | видно, что вообще работает |

Всё это легко откатить: файлы лежат в `/etc/sysctl.d/` и `/etc/environment`.

## Что специально НЕ сделано

- **Нет своего ядра.** Штатное `linux` стабильнее. CachyOS-ядро (BORE) —
  опция, см. `pacman.conf` в профиле.
- **Нет агрессивных таймеров** (`HZ=1000`, `preempt=full`): это ломает
  звук и увеличивает энергопотребление на ноутбуках.
- **Нет `preload`/`zswap` одновременно**: конфликтуют.
- **Нет автозапуска AUR-хелпера от root**: сборка AUR от root запрещена
  политикой makepkg.
