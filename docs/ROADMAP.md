# Roadmap FarchiOs

## v0.1 «forge» — текущее состояние

- [x] archiso-профиль, BIOS + UEFI
- [x] KDE Plasma 6 + SDDM (автологин в live)
- [x] Игровой стек из официальных репозиториев
- [x] `farchios` CLI: welcome / info / doctor / gpu / tune / gaming / install
- [x] `farchios-gpu-setup` с автоопределением AMD / Intel / NVIDIA
- [x] `farchios-firstboot` и `farchios-postinstall`
- [x] Тюнинг: sysctl, zram, udev, limits, сервисы
- [x] Брендинг: os-release, лого, обои, fastfetch
- [x] Сборка через Docker / WSL2 / Arch
- [x] CI-сборка ISO

## v0.2 — «установка без боли»

- [ ] Calamares с брендингом FarchiOs (как альтернатива archinstall)
- [ ] `farchios-install --auto` — установка в один флаг с разметкой диска
      (btrfs + subvolumes + snapper)
- [ ] `farchios snapshot` — обёртка над snapper, откат после неудачного
      обновления
- [ ] Проверка Secure Boot и подсказки по MOK
- [ ] Автовыбор зеркал при установке (reflector в postinstall)

## v0.3 — «производительность»

- [ ] Своё ядро: `linux-farchios` на базе 6.x + BORE-планировщик

- [ ] Свой репозиторий пакетов с подписью
- [ ] `farchios-bench` — сравнение FPS до/после тюнинга
- [ ] Профили MangoHud под разное железо

## Чего в roadmap не будет

Осознанные «нет», чтобы не обещать лишнего:

- **Собственный пакетный менеджер.** pacman + AUR — главное преимущество Arch.
- **Свой форк glibc/systemd.** Это путь к несовместимости.
- **Обход античитов.** Юридические и этические проблемы, баны у пользователей.
- **Отдельный «игровой» режим с перезагрузкой.** Лишняя сложность.

## Как выбрать следующий шаг

По влиянию на пользователя:

1. Calamares и `--auto` установка — снимает главный барьер.
2. Своё ядро с BORE — измеримый прирост FPS/латентности.
3. Свой репозиторий — без него невозможно нормально обновлять пакеты
   дистрибутива.
